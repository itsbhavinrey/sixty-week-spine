# P2.3 — `orm-xray`

> Eight queries, written twice - raw SQL and Drizzle - with the SQL each one actually emits and what the planner does with it.

**Phase 2** · ships week 13 · Neon + Cloudflare Pages · difficulty Low
**Spec:** [`plan/01-roadmap.md`](../../../plan/01-roadmap.md) → search `P2.3`

## Why this one

This is the phase's argument for itself. Having written raw SQL by hand in
[`P1.1`](../../phase-1/projects/P1.1.md) and designed the schema in
[`P1.2`](../../phase-1/projects/P1.2.md), you can now put an ORM next to raw SQL and judge
it — impossible in phase 1, because the comparison only means something if you can read the
plan. It sits right after [`P2.2`](P2.2.md) for a reason: the API layer is where you first
wanted an ORM and refused, and this week decides whether `driftwatch`'s later layers adopt
one. Nothing downstream depends on this repo, but that decision follows the spine to the end.

## What you'll be able to do after

- You will have captured the SQL an ORM call actually emits and can show, not assert, what
  the abstraction did with your intent.
- You will have read the plan for both versions of the same query and can say which is worse
  and why, in planner terms rather than opinion.
- You will have found at least one query where the ORM lost, fixed it, and can explain the
  fix.
- You will be able to answer "when would you drop to raw SQL" with a case from your own repo.

| 1 | One query both ways, with the emitted SQL captured | first hour | You can see the exact string the ORM sent to Postgres |

**Definition of done** — the table has eight rows, each showing both queries and both plans,
and one row is the ORM losing with the fix beside it. Then the ship checklist in
[`../README.md`](../README.md) is green.

## Where you'll get stuck

- **The ORM's docs describe syntax the installed package does not have** — a docs site and a
  registry's default tag can be describing different releases, so you will follow a guide and
  get errors that make no sense → pin the exact version you installed, say so in the README,
  and check [`../verified/`](../verified/) for which is which. The spec flags this trap
  explicitly; catching it is worth telling an interviewer about.
- **Both plans look identical** — on a handful of rows the planner sequentially scans
  everything, so a comparison at that size measures nothing → load enough rows (reuse
  [`P1.1`](../../phase-1/projects/P1.1.md)'s dataset), then let the statistics update before
  you `EXPLAIN` anything.
- **The N+1 hides inside one line of TypeScript** — relation loading looks like a single call
  at the call site → count queries from the driver log rather than eyeballing the code; the
  log is the only ground truth here.
- **You cannot get the emitted SQL out at all** — this is where the 2-hour rule fires. If the
  driver's logging hook resists, read the database's own statement log instead. Getting the
  hook working is not the deliverable; the table is.

## The interview angle

"What query does this ORM call actually run" is a standard India PBC screen, and this repo is
that answer with evidence attached. So is "when do you drop to raw SQL", and the pinning
story doubles as "tell me about something you caught that the docs got wrong". The
system-design rep is smaller but real: where a data-access abstraction stops paying for
itself, and what finding that out in production costs instead. Resume line: *eight queries
written raw and through an ORM, with emitted SQL and plans side by side, and the one case the
ORM got wrong.* The follow-up is "did you benchmark it" — honest answer: no, deliberately.
Wall-clock timings against a database that scales to zero mostly measure the cold start, so
the comparison is on plans.

## Scope discipline

**Out of scope** — no Prisma comparison; a second ORM doubles the capture work for a third
column nobody asked for. No benchmarking harness — see the follow-up above. No verdict on
which is "better": a README that picks a winner is weaker than one that shows the plans.

**Stretch** — add the same eight in Prisma and make it a three-way table. Only after the ship
checklist is green.
