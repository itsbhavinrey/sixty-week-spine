# P2.1 — `typed-api-contract`

> A client and server that cannot disagree, and eight bugs the type system refuses to compile.

**Phase 2** · ships week 10 · Cloudflare Workers + Pages · difficulty Low
**Spec:** [`plan/01-roadmap.md`](../../../plan/01-roadmap.md) → search `P2.1`

## Why this one

This is the technique rehearsal that makes [`P2.2`](P2.2.md) an afternoon rather than a week.
Its one trick — a single schema module emitting both compile-time types and runtime
validators, consumed by a server and a client that never share a build — is what
`driftwatch`'s API layer needs two weeks later, and you do not want to be learning it while
also designing pagination and idempotency. That is the answer to "why is a low-difficulty
project sitting at week 10": it is deliberately toy, so the technique is the only hard part.
Week 9 gave you strict mode, generics and unions; week 10 adds conditional and mapped types,
`satisfies`, and validation at the boundary. This is where you spend them.

## What you'll be able to do after

- You will have written the shared schema module yourself and can explain why a boundary
  needs a runtime validator *and* a static type, and what each catches that the other cannot.
- You will have written a typed fetch client and can explain how the response type reaches
  the call site with no code generator anywhere.
- You will have caused eight compile errors on purpose and can name the class of production
  bug each one refuses to ship.
- You will have hit the limit of what the type system can express and can say where it is.

## Build plan

| # | Milestone | Roughly | Done when |
|---|---|---|---|
| 1 | Repo from `ship-kit`, strictest settings, one endpoint round-tripping | first hour | Client → Worker → typed response, no `any` in the path |

| 3 | Typed client; `satisfies` where an annotation would widen a type | a quarter | You can point at the line where an annotation killed a union |
| 4 | `bugs/` — eight commented lines with captured errors; deploy | remainder | Uncommenting any one fails the build with the documented message |

**Definition of done** — a stranger clones the repo, uncomments a line in `bugs/`, runs the
type checker and gets the exact error the README promised. Then the ship checklist in
[`../README.md`](../README.md) is green.

## Where you'll get stuck

- **Types are perfect, runtime still receives garbage** — a validated boundary holds only if
  nothing bypasses it, and one assertion re-opens the hole → grep your own repo for
  assertions and `any` before believing the guarantee.
- **`satisfies` versus an annotation** — you will annotate an object, watch a literal union
  widen to `string`, and lose the inference downstream → write the two-line difference into
  the README instead of looking it up again in phase 3.
- **The errors you documented change under you** — error text is a function of the toolchain,
  so a hand-copied message is a hostage → paste messages from a CI run and pin the toolchain
  exactly rather than following a moving tag ([`../verified/`](../verified/) owns which
  versions those are, not this file).
- **The type you cannot express** — one conditional or mapped type will almost work for
  hours. The 2-hour rule fires here: falsifiable sentence, smallest failing type, and if it
  still resists, move it into the README's honest note.

## The interview angle

It answers "how do you stop a client and a server drifting apart" without the answer being a
framework name, and lets you discuss parse-don't-validate from having done it. The
system-design rep is boundary placement: which layer may trust its input, and what moving
that line costs. Resume line: *a client and server sharing one schema module, with eight
classes of API drift demonstrated as compile errors.* The follow-up is "why not tRPC" —
honest answer: tRPC assumes both ends in one repo and this contract had to survive a client
that is not.

## Scope discipline

**Out of scope** — no tRPC: a monorepo-only tool that hides the mechanism you are here to
learn. No code generation; a build problem that would eat the hours the eight bugs need. No
real domain — once this grows a schema worth arguing about it competes with `driftwatch`.

**Stretch** — a branded-type example where a `UserId` and an `OrgId` cannot be swapped. Only
after the ship checklist is green; a stretch that eats the ship is a failure, not an upgrade.
