# P2.2 — `driftwatch` · driftwatch layer 3

> A REST API you could hand to a stranger: cursor pagination, idempotent writes, machine-readable errors, and an OpenAPI contract.

**Phase 2** · ships week 12 · Cloudflare Workers + Neon · difficulty Medium
**Spec:** [`plan/01-roadmap.md`](../../../plan/01-roadmap.md) → search `P2.2`

## Why this one

Layer 2 gave `driftwatch` a schema and a memory ([`P1.2`](../../phase-1/projects/P1.2.md));
the only way in is still the CLI on your own machine. This layer adds the HTTP surface over
that schema — what turns it from a script into a service other people and other processes can
use. It comes after the schema because there is no honest API design without knowing what the
rows look like, and before auth because [`P3.4`](../../phase-3/projects/P3.4.md) bolts
tenancy and roles onto these endpoints and every layer after that assumes they exist. Week 11
is the design reading; [`P2.1`](P2.1.md) rehearsed the typing, so week 12 goes on API
decisions.

## What you'll be able to do after

- You will have implemented cursor pagination yourself and can defend it against offset in
  three lines, with the failure case that decided it.
- You will have implemented an idempotency key with stored replay and can say what happens
  when the same key arrives twice, concurrently, or with a different body.
- You will have written one error shape for every failure in the service and can say why a
  machine-readable error is not just a nicer error string.
- You will have hand-written and served an OpenAPI document and can say what that bought you
  over emitting one from code.

## Where you'll get stuck

- **Your cursor is an offset in a costume** — encoding a row count still shifts results when
  rows are inserted, because a cursor is a position in a total order, not a count → sort on a
  stable pair (timestamp plus id) and encode both; the tie-break is the whole trick.
- **Idempotent replay races itself** — a retry arrives while the first request is still
  running, so "store the response when you finish" leaves a window that creates two scans →
  insert the key first in an in-progress state and let a unique constraint reject the second.
  Decide explicitly what a key reused with a different body returns.
- **Serverless plus Postgres connections** — each invocation wants its own connection, so the
  symptom is intermittent failure under concurrency rather than a clean error → use the
  connection method this deploy target expects, and check [`../verified/`](../verified/) for
  which one that is. Fire the 2-hour rule here early: reduce to one deployed Worker
  making one query and fix it there, not inside the route handlers.
- **The hand-written spec drifts from the code within a week** — nothing enforces it → leave
  the hook for [`P2.4`](P2.4.md) to assert responses against the document; do not close that
  loop this week.

Two spine layers and two spurs make phase 2 the densest stretch before phase 6. Week 15 is a
buffer and [`plan/03-reality-check.md`](../../../plan/03-reality-check.md) says you will need
it. If this slips it takes buffer, not phase 3's first week.

## The interview angle

"How do you make a `POST` safe to retry" is a standard India PBC screen, and stored replay
with a concurrency story behind it is the good version of that answer. Cursor versus offset,
and versioning with a stated deprecation policy, are two more. The system-design rep is the
contract itself: what a client may depend on, and how you change it without breaking them.
Resume line: *a versioned, paginated, idempotent REST API with a published OpenAPI contract.*
The follow-up is "how does your rate limit behave across instances" — honest answer: it does
not yet, because distributed limiting needs the shared state that arrives in phase 5.

## Scope discipline

**Out of scope** — no auth: that is [`P3.4`](../../phase-3/projects/P3.4.md) and would double
the week. No GraphQL, no webhooks (a delivery-retry problem, not an API design one), no SDK
generation.

**Stretch** — generate a typed client from your own OpenAPI document and use it in the CLI.
Only after the ship checklist is green.
