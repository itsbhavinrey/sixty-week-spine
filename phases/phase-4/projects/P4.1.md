# P4.1 — `slimjim`

> One Node service, five Dockerfiles, and the numbers that show which choices actually matter.

**Phase 4** · ships week 21 · GHCR (images are the artifact) · difficulty Low
**Spec:** [`plan/01-roadmap.md`](../../../plan/01-roadmap.md) → search `P4.1`

## Why this one

Docker was named out of scope in [`P0.1`](../../phase-0/projects/P0.1.md) — `ship-kit`'s spec
defers containers to this phase by name — and here is where that comes due. Twenty weeks of
serverless deploys means you have never had to care what a layer is. Every later project that
cannot get a live URL ships as `docker compose up` plus an asciinema cast instead:
[`P7.1`](../../phase-7/projects/P7.1.md), [`P7.3`](../../phase-7/projects/P7.3.md),
[`P7.4`](../../phase-7/projects/P7.4.md), and this phase's own [`P4.3`](P4.3.md) stretch. It
is also the lowest difficulty here, placed right after the auth grind on purpose.

## What you'll be able to do after

- You will have written five Dockerfiles for one service and can explain, with your own
  measured numbers, what each rung of the ladder bought and what it cost.
- You will have broken your own layer cache on purpose and can explain why `COPY` order
  decides whether a one-line source change rebuilds in seconds or minutes.
- You will have run a distroless and then a rootless container and can say what debuggability
  you gave up and what attack surface you removed.
- You can explain why a published image is the deliverable here rather than a URL.

## Where you'll get stuck

- **A one-character source edit reinstalls every dependency** — the `COPY` of the whole tree
  sits above the install step, so everything after it is invalidated → copy manifests first,
  install, then copy source. This is the deliberate mistake the README shows, so keep it.
- **The distroless container exits silently and you cannot get a shell** — there is no shell
  and no package manager to add one → debug in the build stage, or use the debug variant of
  the base image. Do not solve it by going back to a full base.
- **Rootless breaks on file ownership or a low port** — the process no longer owns paths the
  build wrote, and cannot bind a privileged port → set ownership at `COPY` time, move the
  listener up. Two-hour rule fires here: "permission denied" has three unrelated causes.
- **Pulls start failing in CI** — shared CI egress addresses hit registry pull limits that
  have nothing to do with you → authenticate in CI and prefer GHCR. Current position on those
  limits: [`../verified/`](../verified/).

## The interview angle

This answers "why is your image that size" and "what happens on a rebuild" — the container
questions mid-level loops actually ask. The system design rep is build-time versus run-time
separation, and why cold start is a deployment property rather than a code property. Resume
line: *five container builds of one Node service, benchmarked and published to a public
registry.* A good interviewer asks next about multi-arch or base-image provenance; the honest
answer is that multi-arch is the stretch and signing is [`P4.2`](P4.2.md).

## Scope discipline

**Out of scope** — no Kubernetes (that is [`P7.4`](../../phase-7/projects/P7.4.md), and
pulling it forward eats the phase); no architectures beyond the two mainstream ones, since a
third doubles every row of the table; no runtime flag tuning, a rabbit hole with no artifact;
no comparison against other JavaScript runtimes, which changes the subject.

**Stretch** — a `docker buildx` multi-arch build published with attestations, after the
checklist is green. Attestations are the seam into `P4.2`, which makes it tempting; it is
still a stretch.
