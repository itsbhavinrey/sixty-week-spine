# P0.2 — `driftwatch` · driftwatch layer 1

> Point it at a package.json and it tells you how far behind you are - latest version, release date, and how long since the project last shipped anything.

**Phase 0** · ships week 2 · npm + asciinema · difficulty Low
**Spec:** [`plan/01-roadmap.md`](../../../plan/01-roadmap.md) → search `P0.2`

## Why this one

This is layer 1 of the eight-layer spine that runs to week 60, and for now it is the whole of
`driftwatch`: read a manifest, ask the registry about every dependency, report how stale each
one is. Every later layer builds on this one — layer 2
([`P1.2`](../../phase-1/projects/P1.2.md)) gives it a memory, so scans persist and you can ask
what changed since last week; layer 3 ([`P2.2`](../../phase-2/projects/P2.2.md)) puts an API in
front of it. The staleness heuristic here is the one the currency audit in
[`plan/00-currency-audit.md`](../../../plan/00-currency-audit.md) applied by hand across ~130
tools, so you already know the problem is real and know what good output looks like. Its only
dependency is [`P0.1`](P0.1.md): this is the first repo built from the template, and a CLI is
the smallest thing that produces a real answer.

## What you'll be able to do after

- You will have published a Node CLI yourself, and can explain what happens between someone
  typing `npx driftwatch` and your code running.
- You will be able to state precisely what "behind" means — the range in the manifest, what is
  installed, and what the registry serves are three different things.
- You will have written a bounded concurrent client with per-item failure handling, and can say
  what your tool does when one package is unreachable.
- You will be able to defend the staleness heuristic *and* name where it lies: a small, finished
  library looks abandoned by the same signal.

## Where you'll get stuck

- **Your "behind by" number disagrees with the package manager's** — the tag a registry points
  at is not always the highest version by semver, and a maintainer can publish a patch on an old
  major → pick which of the two you report, write that choice into the README, and test it
  against a package that has both.
- **One odd dependency kills the whole scan** — scoped, unpublished, private or workspace deps
  return nothing, and an unhandled rejection takes the process with it → settle per-package
  failures into a reported "unknown" row before you build the table, and make it a test case.
- **Flaky on big manifests, fine on small ones** — unbounded parallel requests get throttled or
  reset, and results arrive in nondeterministic order → cap the pool, back off on retry, and
  sort output by name rather than completion.
- **It runs locally and fails through npx** — the shebang, the `bin` entry, the published file
  list and the module format are four separate ways to break distribution → the 2-hour rule
  fires here: pack the tarball, install it into an empty directory, reproduce there.

The spec calls this low difficulty. If it takes more than one week's hours, that is useful
information about where your TypeScript actually is, not a failure.

## The interview angle

It answers "tell me about something you built that other people run", a stronger opening than
any tutorial repo. The system-design rep buried in it is a fan-out read path against a
third-party API you do not control: bounded concurrency, retries, partial failure, deterministic
output. Resume line: "published a dependency-staleness CLI that scores a manifest against the
registry — the first layer of a service that grew to an API, queues and retrieval." The
follow-up is "what happens when the registry is slow, or the manifest has ten thousand
dependencies" — the honest answer is that nothing is cached and every run refetches, which is
the problem layer 2 exists to fix.

## Scope discipline

**Out of scope** — no server, no database, no LLM, no GitHub integration, no other package
ecosystems. Each is a later layer or a deliberate never, and any one turns a week into three.

**Stretch** — a `--budget` flag that fails CI when a dependency is more than N majors behind.
Only after the ship checklist is green.
